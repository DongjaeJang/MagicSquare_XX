## 3. Mom Test 결과

### 3.1 진짜 문제 (한 문장)

> 4×4 부분 마방진(`?` 2칸)을 **손으로** 채운 뒤 **10선(행·열·대각선) 합 34**를 확인할 때 **대각선을 까먹어** 처음엔 틀린 상태로 **20분**을 쓰고, **다 채운 뒤에야** 틀렸다는 걸 알며 **`?` 두 칸만 고친 뒤 10선 전부를 다시 더해** 맞춘다.

### 3.2 Mom Test 증거 3줄

| # | 인용 | Mom Test 적합성 |
|---|------|-----------------|
| 1 | “**오늘** … **20분** 걸렸는데 못 풀었어. **대각선 하나를 빼먹었**거든” | ✅ **과거·비용·실수** |
| 2 | “**다 채우고 나서**” (틀렸다는 걸 알았다) | ✅ **발견 시점** |
| 3 | “**두 칸만 고쳤어**” → “**다시 더해서 맞췄지**” / “**다 확인했다**” | ✅ **수정·재검증 행동** |

### 3.3 표면 문제 (잘못된 정의 — 솔루션 혼입)

Mom Test에서 **문제 정의에 쓰면 안 되는** 문장들:

- “4×4 마방진을 **ECB/BCE로 분류**하고 `MagicSquare` / `Solver` / `GridUI` **프로그램부터 만든다**.”
- “**SquareValidator** / **validate_lines** 테스트를 **먼저** 짜면 된다.”
- “**실패 조건 3개 도출**만 하고 **손풀이 검증**은 나중.”

→ **‘무엇을 만들지’** 만 있고, **불편·비용·과거 행동**이 없음.

## 6. 세션 3 워크북 (Mom Test → R-G-I-O)

### 6.1 주제 (1문장)

> **4×4 부분 마방진에서 빈칸을 채운 직후, 행·열·대각선 10선이 각각 34인지 빠르게 확정하고, 틀리면 어느 줄인지 바로 짚을 수 있게 검증 규칙과 테스트 루프를 만든다.** 미완성 격자(0 포함)는 `incomplete`로 구분한다.

*(솔루션 최소화 — Solver·UI·ECB 전체가 아니라 **판정·확인 비용**만 다룸)*

### 6.2 R-G-I-O

| | 내용 |
|---|---|
| **R — Role** | 4×4 **부분** 마방진 학습자. 빈칸 2개(0)를 1~16으로 채운 뒤 **맞았는지 스스로 확인**해야 함 |
| **G — Goal** | 빈칸 채운 후 **10선 합 34 여부를 즉시 판정**하고, 틀리면 **어느 행·열·대각선**인지 식별 *(20분 낭비 → 처음·한 번에)* |
| **I — Input** | `grid: list[list[int]]` — 4×4 정수 격자. 셀 값 **0**(빈칸) 또는 **1~16** |
| **O — Output** | `validate_lines(grid)` → **ValidationResult**: `ok` (bool), `status` (`"pass"` \| `"fail"` \| `"incomplete"`), `lines[]` — fail 시 **틀린 줄만** `{ id, sum, expected: 34 }`. 줄 ID: `row:0`~`row:3`, `col:0`~`col:3`, `diag:main`, `diag:anti`. **R5:** 격자에 `0`이 하나라도 있으면 `status=incomplete`, 합 계산·34 비교는 수행하지 않음 |

### 6.3 성공 기준 3개 (Mom Test 증거 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| 1 | **`validate_lines(grid)`** 한 번으로 **10선×34 검증**을 수행한다 (행 4 + 열 4 + 대각 2) | “**대각선 하나를 빼먹었**거든” → 줄 누락 방지 |
| 2 | Test Loop **Red→Green**: Red — 합≠34 → `ok=false`, `status=fail`; Red — `0` 포함 → `status=incomplete` (T3); Green — 정답 격자 → `ok=true`, `status=pass` (T1) | “**20분** 걸렸는데 못 풀었어” → 같은 실패를 테스트로 **1번에 재현** |
| 3 | fail 시 `lines[]`에 **틀린 줄 ID**(`row:2`, `diag:main` 등)와 `sum`, `expected: 34`를 반환한다 (10선 전부 검사, 줄 누락 없음) | “**다 채우고 나서**” 알았다 → **줄 단위**로 바로 짚어야 “**두 칸만 고쳤어**”가 빨라짐 |

### 6.4 표면 문제 — 이번 프로젝트에서 하지 않을 것

| 하지 않음 | 이유 (Mom Test) |
|-----------|-----------------|
| ECB/BCE 전체 · `GridUI` · `InputHandler` | UI·입력은 **표면 솔루션** — 이번 고통은 **맞는지 판정·확인** |
| `Solver` · 빈칸 자동 채우기 · 힌트 | 학습자 고통은 **풀기**보다 **10선 검증 누락·20분 낭비** |
| ECB 분류·실패 조건 도출만 하고 테스트 없음 | “**다시 했음**”처럼 **재현·검증 없는 설계표**는 Mom Test 비용을 줄이지 못함 |
| 1~16 중복·범위 검증까지 한꺼번에 | 세션 3 범위 밖 — **합 34 판정**에 집중 |

### 6.5 8계층 — 이번 세션에서 만들 것만

| 계층 | 세션 3에서 할 일 | Mom Test 연결 |
|------|------------------|---------------|
| **Rule** | R1~R4: **행·열·대각선 합 = 34** 판정. R5: `0`(빈칸) 포함 시 `status=incomplete` (**fail과 구분**, 합 검증 생략) | “**대각선 하나를 빼먹었**거든” → **10선 판정 기준**을 코드·문서로 고정 |
| **Command** | `validate_lines(grid)` → `ValidationResult` — 10선 합 계산 + 34 비교 + fail 시 **틀린 줄 ID·sum·expected** 반환 | “**다시 더해서 맞췄지**”를 **한 Command**로 대체 |
| **(Skill)** | *(선택)* pytest 실행 / 격자 fixture 준비 Skill | 매번 손으로 10선 더하기·**까먹음** 제거 |
| **Test Loop** | Red: 합≠34 → `ok=false`, `status=fail`, **실패 줄** assert; Red: `0` 포함 → `status=incomplete` (T3); Green: 정답 격자 → `ok=true`, `status=pass` (T1) | **20분 낭비** → **같은 실패를 테스트로 고정** |

**이번 세션에서 만들지 않음:** Entity(`MagicSquare`/`Cell`), Boundary(`ResultDisplay`), Solver, MissingFinder, ECB 전체
